# 09 · Cross-browser and mobile review (read-only)

Scope: `web/src` on `main` plus `traktor-wt2/{ui,report}/web/src` (the v2 lanes; map, card and deck code is the same in both, and wt2 adds `use(browser())`). Paths below are relative to `traktor-wt2/ui/web/src` unless they start with `main:`.
Method: grepped for risky APIs, read the map, deck, card, PointCloud and v2 helper code, and inspected the compiled CSS of the existing main build. I took headless Edge screenshots of `/mapa`, `/slides` and `/karta` at 390×844 and 1440×900 (copies in `%TEMP%\trk-shots`), then stopped the server.
**Caveats:** (1) the `.next` build was **stale**: it still shows the basemap toggles "Satelita/Ortofoto/Mapa/Schemat", so it predates the current code. (2) Headless Chromium on Windows has a minimum viewport of about 500 px, so cut-offs at the right edge in the 390 px shots may come from the headless setup. The findings below rest on the code. Re-check them in DevTools device mode or on a real phone.

## Baseline (read this first)
- **Safari on Windows does not exist** (the last version was 5.1.7, from 2012). In practice "Safari" means macOS or iOS Safari. Say this to the jury and test on a Mac or iPhone, or with BrowserStack.
- **Opera** is Chromium-based, so everything that works in Chrome works there. One risk: Opera's built-in ad blocker could block `nominatim.openstreetmap.org` (v2 geocode). Test once with the blocker on.
- Tailwind 4.3 sets the floor at **Chrome/Edge/Opera 111+, Firefox 128+ and Safari 16.4+**. The compiled CSS uses 58 `@property` rules, `@layer` and `oklab`/`lab()`, with `@supports` fallbacks for `color-mix`. Every currently supported version of the 5 target browsers meets this floor. Older Safari (15 and below) would render shadows and transforms wrong.
- Already fine, no action needed: `h-dvh` (MapApp:177) and `100svh` (app/page.tsx:73) work in all targets. Wheel zoom uses `{passive:false}` correctly (MapCanvas:158). Map pan uses Pointer Events with capture, which works in all browsers. `vector-effect=non-scaling-stroke` inside the viewBox scaling: Safari supports it, and strokes inside the transformed tile `<g>` don't use it. `localStorage`, `inert`, `:has`, `<dialog>` and `type=date` are **not used** anywhere yet.

## Suggested order (≈2 h)
1. #1 + #2 + #3: a mobile map that can actually be used (sheet peek, zoom above the sheet, pinch, one-row scenario bar).
2. #4: karta at phone widths (scale to fit).
3. #5: attribution always visible.
4. #7, #13, #14: small guards in keyboard and fullscreen handling.
5. Rebuild, then test each of the 5 browsers in this order: Chrome → Edge → Opera (same engine, a quick smoke test), then Firefox (print, fonts), then Safari on Mac/iPhone (fullscreen, print, tiles).
