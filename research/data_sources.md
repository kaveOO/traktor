### Gap analysis

Derived only from the facts above:

- **Satellite drought monitoring is already sold.** SatAgro has a soil-moisture-deficit and drought-loss module at 5–9 €/ha/yr, and OneSoil offers moisture imagery on a freemium model. A drought-NDVI dashboard alone would not be differentiated.
- **National drought status is free but coarse.** IUNG SMSR and IMGW Agrometeo publish it at gmina or national-map level, with no API. Aplikacja suszowa uses gmina-level KBW, and farmers publicly dispute the results. No independent per-parcel evidence tool was found (UNVERIFIED as absent).
- **No DEM-based weir/zastawka siting or operation tool for Polish farmers was found.** The search was incomplete, so this is UNVERIFIED as absent, not proven. The only related items are the NWRM catalogue entry (A14), educational content and an academic DSS.
- **The inputs for such a tool are open and verified:** national ditch geometry (BDOT10k `OT_SWRM_L`), a 1 m DTM and point-height service, the 5 m soil drought-susceptibility raster and flood hazard WMS.
- **The legal and funding context fits the product.** Holding water in ditches without structures is permit-exempt (art. 395 pkt 11–13), and rebuilding needs only a powiadomienie. Physical zastawki need a pozwolenie wodnoprawne. Maintenance is the owner's or spółka wodna's job. Funding exists: regional grants up to 100k PLN, the TUZ ekoschemat, and the Wody Polskie programme. So a screening tool can route each candidate site to the matching legal path and funding.
- **The measured benefit is retention and outflow reduction:** 23%→41% usable ditch storage, and −30.5% outflow. Yield gains are not evidenced in Poland.

## 5. Recommended MVP data stack (ditch-weir / controlled-drainage screening)

Every source here was verified live. Templates show the call that was actually made, with placeholders.

1. **Ditches: BDOT10k `OT_SWRM_L`** (VERIFIED, HEAD 200, ~159 MB)
   `GET https://opendata.geoportal.gov.pl/bdot10k/schemat2021/GeoParquet/OT_SWRM_L.parquet`
   Download once, then clip to the AOI (for example with DuckDB or GeoPandas). OSM Overpass `waterway=ditch|drain` per bbox is an optional supplement.

2. **Terrain: GUGiK NMT 1 m**
   - **Point heights, VERIFIED:** `GET https://services.gugik.gov.pl/nmt/?request=GetHByXY&x={x2180}&y={y2180}` returns plain text such as `113.3`.
   - **Batch heights:** `GET https://services.gugik.gov.pl/nmt/?request=GetHByPointList&list={x1}%20{y1},{x2}%20{y2}&json` returns `x y h,x y h`. Coordinates must be **EPSG:2180**. Use this for ditch long profiles (bed slope gives weir spacing).
   - **AOI tiles:** WCS 2.0.1 `https://mapy.geoportal.gov.pl/wss/service/PZGIK/NMT/GRID1/WCS/DigitalTerrainModelFormatTIFF?SERVICE=WCS&VERSION=2.0.1&REQUEST=GetCapabilities` (VERIFIED), CoverageId `DTM_PL-KRON86-NH_TIFF`. A GetCoverage with `SUBSET` on a 100 m bbox **timed out on 2026-11-20 by fetch**, so the GetCoverage pattern is UNVERIFIED. Fall back to the point-list service or Copernicus DEM `COPERNICUS_30`.

3. **Parcel: ULDK** (VERIFIED)
   - By location: `GET https://uldk.gugik.gov.pl/?request=GetParcelByXY&xy={lon},{lat},4326&result=geom_wkt,teryt,voivodeship,county,commune&srid=4326`
   - By ID: `GET https://uldk.gugik.gov.pl/?request=GetParcelById&id={teryt_id}&result=geom_wkt,teryt`
   - The response starts with line `0` (OK), followed by `SRID=...;POLYGON(...)|teryt`.

4. **Observed weather and warnings: IMGW** (VERIFIED)
   - `GET https://danepubliczne.imgw.pl/api/data/meteo` (10-min precipitation `opad_10min`)
   - `GET https://danepubliczne.imgw.pl/api/data/synop`
   - `GET https://danepubliczne.imgw.pl/api/data/hydro`
   - `GET https://danepubliczne.imgw.pl/api/data/warningshydro` (filter `zdarzenie == "Susza hydrologiczna"`) and `.../warningsmeteo` (the response is an object with `message` when there are no warnings)
   - Attribution: "Źródłem pochodzenia danych jest Instytut Meteorologii i Gospodarki Wodnej – Państwowy Instytut Badawczy".

5. **Forecast and running KBW: Open-Meteo** (VERIFIED; non-commercial, CC-BY 4.0)
   - Forecast: `GET https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&hourly=soil_moisture_0_to_1cm,soil_moisture_3_to_9cm,et0_fao_evapotranspiration,precipitation`
   - History: `GET https://archive-api.open-meteo.com/v1/archive?latitude={lat}&longitude={lon}&start_date={YYYY-MM-DD}&end_date={YYYY-MM-DD}&daily=precipitation_sum,et0_fao_evapotranspiration`
   - KBW = Σ(P − ET0) over 60 days. Compare with the IUNG thresholds at `susza.iung.pulawy.pl/progi/`.

6. **Flood hazard: ISOK MZP WMS** (VERIFIED; re-verified 2026-11-20 by fetch)
   - `GET https://wody.isok.gov.pl/gpservices/KZGW/MZP20_Glebokosc_NiskiePrawdopodPowodzi/MapServer/WMSServer?SERVICE=WMS&REQUEST=GetCapabilities` returns WMS 1.3.0. Then use GetMap per layer.
   - Use this to exclude or flag weirs in flood zones. Optional: EMSR756 as a 2024 historical overlay.

7. **Soil drought susceptibility: IUNG WCS** (VERIFIED; GetCoverage verified 2026-11-20 by fetch)
   - `GET https://sgeo.iung.pl/geoserver/ows?service=WCS&version=2.0.1&request=GetCoverage&coverageId=Susza__katgl_landuse2024&subset=y({min},{max})&subset=x({min},{max})&format=image/tiff`
   - Axis labels are `y x` (labels `E`/`N` are rejected with `InvalidAxisLabel`). The CRS is EPSG:2180, with native envelope lowerCorner `133120 171570` and upperCorner `775030 862010`. Check the returned GeoTIFF georeferencing to confirm which axis is easting before using it in production.
   - Category I (sands) gives the strongest case for retention.

8. **Optional wet-persistence: CDSE Sentinel Hub Statistical API, S1 GRD** (PARTIAL; free tier 10k requests and 10k PU per month)
   - `POST https://sh.dataspace.copernicus.eu/api/v1/statistics` with OAuth2 client credentials. Use the ULDK polygon as geometry and a backscatter time series as the wetness proxy.
   - The exact request was not executed in either report, so the call pattern is UNVERIFIED.

Context layers worth adding if time allows: MPHP10k WMS (catchments and watercourses) and EDO WMS `cdiad` / `smian` (regional drought).
